> 유료 앱 1건(iOS·Android, 2026년 8–9월 출시)과 무료 앱 1건을 실제로 스토어에 내면서 겪은 것을 정리했다. 세 번째 앱은 등록 준비 중이다.
> **개발 자체는 AI가 대부분 해준다. 시간과 손이 가는 건 이 문서에 있는 것들이다.**
> 각 항목의 ⚠️는 실제로 걸려 넘어진 지점이다.

## 1. 장비

- **맥은 선택이 아니다.** iOS 빌드·아카이브·업로드가 맥에서만 된다. 클라우드 맥 대여도 가능하지만 인증서/키체인이 얽혀 번거롭다.
- **안드로이드 실기기 1대.** 에뮬레이터로는 못 잡는 게 있다(실제 결제 흐름, 광고 SDK 노필, 기기별 폰트·IME).
- 아이폰은 없어도 시뮬레이터로 상당 부분 되지만, 결제·푸시·ATT는 실기기가 필요하다.

## 2. 개발자 계정

### Apple Developer Program — $99/년
- 개인(Individual) 또는 조직(Organization)으로 등록한다. **개인으로 등록하면 D-U-N-S가 필요 없다.**
  (조직으로 등록할 경우엔 Apple도 D-U-N-S를 요구한다.)
- 세금 서식은 **Individual/Sole proprietor**로 제출했다 — 개인사업자는 W-8BEN-E가 아니라 **W-8BEN**.

### Google Play Console — $25 1회 ⭐ **가장 먼저 시작해야 하는 관문**

⚠️ **개인 계정으로 만들면 "비공개 테스트 20명 · 14일" 요건에 걸린다.**
2023년 11월 이후 만든 개인 계정은 프로덕션 출시 전에 **실제 테스터 20명을 모아 14일간** 돌려야 한다.
지인 20명을 모으는 게 생각보다 큰일이고, 못 모으면 출시 자체가 안 된다.

**조직(사업자) 계정은 이 요건이 면제된다.** 그런데 조직 계정을 만들려면:

```
D-U-N-S 번호  →  Play 조직 계정  →  20명·14일 테스트 면제
   (1–2주)
```

- ⚠️ **D-U-N-S 발급이 이 과정에서 제일 오래 걸리고 제일 까다롭다.**
  Dun & Bradstreet에 사업자 정보를 등록하고 번호를 받는데, 무료지만 **1–2주**가 걸리고
  상호·주소·대표자명이 사업자등록증과 정확히 일치해야 한다. 불일치하면 반려되고 다시 기다린다.
- ⚠️ **개인 계정으로 먼저 만들었다가 나중에 조직으로 전환하는 건 훨씬 더 번거롭다.**
  처음부터 조직으로 만드는 게 맞다. → **앱 기획 단계에서 사업자등록 + D-U-N-S를 먼저 걸어둔다.**
- 기존 출시 이력이 있는 계정이면 개인 계정이어도 요건에 안 걸린다.

**정리하면 순서가 이렇게 강제된다:**
사업자등록 → D-U-N-S 신청(1–2주 대기) → Play 조직 계정 생성 → 앱 등록

개발이 다 끝나고 나서 시작하면 **여기서만 2–3주를 통째로 기다린다.**

## 3. 사업자·법적 관문 — 여기가 진짜 함정

> **Play와 Apple이 서로 다른 관문을 요구한다.** 둘 다 앱 심사와 무관하게 진행되므로
> **심사 대기 중에 병렬로 처리**해야 시간을 아낀다.

### 3-1. 사업자등록 (공통 전제)
홈택스에서 온라인 신청. 업태/종목은 소프트웨어 개발·전자상거래 계열로.

### 3-2. 통신판매업 신고 — **Play 전용, 이거 없으면 제출 자체가 막힌다**
⚠️ Play Console "게시 개요"에서 `계정 세부정보 업데이트` 오류가 뜨며 **검토 전송 버튼이 안 눌린다.**

- 요구값: **전자상거래 라이선스 번호** = 통신판매업 신고번호(`제2026-서울강남-01234호` 형식)
  / **라이선스 대행사** = 신고 수리 관청(관할 시·군·구청명)
- ⚠️ **판매 국가에서 한국을 빼도 우회 안 된다.** 개발자 *거주지* 기준 요건이다.
- 절차:
  1. 거래은행에서 **구매안전서비스 이용확인증** 발급(무료·즉시)
  2. 정부24에서 통신판매업 신고(사업자등록증 + 확인증 첨부, 3일 내외)
  3. 등록면허세 납부(연 4만원대, 지자체별)
  4. Play Console에 번호 입력
- **애플에는 없는 요건**이다. → iOS를 먼저 심사에 넣고 Play는 번호 확보 후 제출하면 시차가 줄어든다.

### 3-3. DSA trader 신고 — **Apple 전용, 미신고 시 EU 전역 배포 중단**
⚠️ 유럽 디지털서비스법. App Store Connect → Business에서 trader로 신고한다.
- 사업자등록증 업로드. 한글 주소 그대로 제출해도 통과했다.
- ⚠️ **신고한 주소·연락처가 EU 지역 앱 페이지에 공개 노출된다.** 집 주소로 사업자를 냈다면 미리 알고 있어야 한다.

### 3-4. 세금·정산
| 항목 | 메모 |
|---|---|
| Paid Apps Agreement (Apple) | **Active여야 유료 판매·정산이 작동**한다. 세금 서식 제출 후 자동 전환 |
| 은행 계좌 | 사업자 계좌. ⚠️ SWIFT는 **본점 코드**를 쓴다(지점 코드 넣으면 반려) |
| **W-8BEN** | 미제출 시 **원천징수 30%**. 개인사업자는 W-8BEN-E 아니고 W-8BEN<br>⚠️ **6.a 외국납세번호(주민번호) 필수** — 비우면 조약 혜택 거부될 수 있다 |
| 조세조약 조항 | ⚠️ 한미조세조약에서 **사용료(로열티)는 14조**다. 12조는 배당이다. 처음에 12조로 잘못 제출했다가 정정한 적이 있다 |
| Certificate of Foreign Status | Type = Individual/Sole proprietor. ⚠️ **Title은 직함(`Owner`)** — 상호명 쓰면 안 된다 |
| Google 세금 정보 | Play Console에서 별도로 또 제출한다. 계좌 유형 = 개인, 폼 = W-8BEN |

## 4. 앱 자체 준비물 (코드 외)

개발이 끝나도 이게 남는다. 스토어별로 다르다.

### 공통
- **아이콘** (iOS 1024², Play 512²)
- **스크린샷** — ⚠️ 기기 크기별로 따로 필요하다(iOS는 6.5"·13" iPad 등). 자동 합성 스크립트를 만들어두면 재사용된다
- **개인정보처리방침 URL** — ⚠️ **웹페이지가 반드시 있어야 한다.** 서버가 필요 없는 앱이어도 도메인이 필요한 이유가 이것
- **지원(문의) 연락처**

### Play 전용 — "앱 콘텐츠" 설문 10종, 전부 필수
개인정보처리방침 / 광고 유무 / 앱 액세스 권한 / **콘텐츠 등급 설문** / 타겟층 / 데이터 보안 /
뉴스 / 코로나19 / 정부 / 금융 기능
- ⚠️ **API로 안 된다. 전부 콘솔에서 손으로 해야 한다.**
- 타겟층은 **13세 이상**으로 두는 게 안전하다. 아동 대상으로 잡으면 별도 규정이 붙는다.

### Apple 전용
- **App Privacy** 설문(수집 데이터 라벨)
- **수출 규정** — 암호화 사용 여부. 해당 없으면 `ITSAppUsesNonExemptEncryption=false`를 Info.plist에 박아두면 매 릴리스 질문이 사라진다
- 심사 연락처(전화번호 포함)

### 가격
- ⚠️ **자동 환산을 그대로 두면 역진적이 된다.** 베트남 가격이 **499,000đ = $19.19**로 미국($14.99)보다 비싼 상태로
  한 달을 방치한 적이 있다. 최대 시장을 가격으로 막고 있었다. 신흥시장은 수동으로 낮춰야 한다.
- ⚠️ **Play는 무료→유료 전환이 불가능하다.** 유료로 낼 거면 앱 생성 시점에 유료로 만들어야 한다.

## 5. 릴리스마다 반복되는 일

첫 출시가 끝나도 매번 손이 가는 부분이다. 자동화해두면 크게 준다.

| 단계 | iOS | Android |
|---|---|---|
| 버전 올리기 | `MARKETING_VERSION` + `CURRENT_PROJECT_VERSION` | `versionName` + `versionCode` |
| 빌드·서명 | 아카이브 → export → 업로드 | AAB 빌드(keystore 서명) |
| 업로드 | ASC에 빌드 등록 → 버전에 연결 | Play에 AAB 업로드 |
| 출시 노트 | 언어별로 전부 | 언어별로 전부 |
| 제출 | Add for Review → **Submit** | 프로덕션 draft → **검토 후 출시** |

- ⚠️ **ASC "Add for Review"는 제출이 아니다.** 제출 목록에 담기기만 하고 **"Submit to App Review"를 한 번 더** 눌러야 한다.
  중간 상태가 화면상 제출된 것처럼 보여서 실제로 하루를 날렸다.
- ⚠️ **Play `draft`도 출시된 것처럼 보인다.** `completed`가 되어야 라이브다.
- ⚠️ **서명 키를 잃어버리면 앱 업데이트가 영구 불가능하다.** Android keystore는 반드시 백업.
  iOS 배포 인증서는 Xcode 클라우드 관리형이라 키체인에서 **UUID 이름으로만** 보이고
  "Apple Distribution"으로 검색하면 안 나온다 — 없다고 오해하기 쉽다.

## 6. 서버가 필요한 경우

앱이 완전 오프라인이면 서버는 필요 없다. 다만 **도메인은 개인정보처리방침 때문에 어차피 필요**하다.

- **도메인**: 연 1–2만원. 네임서버만 붙이면 정적 페이지 호스팅은 무료로도 가능
- **서버**: Oracle Cloud 무료 티어(Always Free)로 충분한 경우가 많다. ARM 인스턴스 + 블록 스토리지가 영구 무료
- ⚠️ **도메인 나이가 마케팅에 영향을 준다.** 페이스북은 **등록 6개월 미만 도메인**을 링크 스팸 신호로 잡는다.
  그 때문에 50만 명 그룹에서 25분 만에 글이 삭제된 적이 있다. **앱 만들기 전에 도메인부터 사두면** 그 시계가 미리 돈다.

## 7. 순서 — 병렬로 하면 몇 주가 준다

```
[제일 먼저 — 기획 단계에서]
  사업자등록 (당일–3일)
    → D-U-N-S 신청 ⚠️ 1–2주 대기, 가장 긴 리드타임
      → Play 조직 계정 생성 (= 테스터 20명·14일 면제)
  통신판매업 신고 (3일–1주)
  도메인 구입 (페북 6개월 시계 미리 시작)
  Apple 개발자 계정 (개인이면 D-U-N-S 불필요)

[개발 마무리쯤]
  세금 서식·은행 계좌·DSA 신고  ← 심사와 무관하게 진행되니 병렬로
  개인정보처리방침 페이지 배포
  아이콘·스크린샷 준비

[제출]
  iOS 먼저 제출 (통신판매업 요건 없음)
  Play는 신고번호 확보 후 제출

[출시 후]
  지역 가격 점검 (역진 확인)
  리뷰 요청 팝업 (평점 0개가 전환율을 가장 크게 깎는다)
```

- [ ] 미국 세금 서식(W-8BEN) — **양쪽 스토어에 각각**. 미제출 시 30% 원천징수
- [ ] 사업자 명의 은행 계좌 + SWIFT 본점 코드

- [ ] 개인정보처리방침 **웹페이지** (서버 없는 앱도 필요)
- [ ] Play 앱 콘텐츠 설문 10종 (콘솔 수동)
- [ ] 스크린샷 **기기 크기별**
- [ ] 서명 키 백업 (분실 = 업데이트 영구 불가)
- [ ] 지역 가격 역진 확인
- [ ] 심사 "제출" 버튼이 두 단계라는 것
- [ ] **D-U-N-S를 기획 단계에서 미리 신청** (1–2주 + 정보 불일치 시 재신청)

## 9. 정리

**개발은 이제 병목이 아니다.** 단어 데이터 파이프라인·앱·웹까지 AI가 대부분 썼다.
실제로 시간이 든 곳은 **사업자·세무·법적 신고 관문**과 **스토어 설문·자산 준비**,
그리고 **출시 후 마케팅**이었다.

한국 개발자 기준으로 기억할 것은 딱 두 줄이다.

> **Play = 통신판매업 신고**가 없으면 제출 버튼이 안 눌린다.
> **Apple = DSA trader 신고 + 미국 세금 서식**이 없으면 EU 배포가 막히고 30%가 원천징수된다.
