# 인계 — vibearchive를 기록 공개 표면으로 쓰기 (2026-09-16)

business-ideas 세션에서 내린 결정이다. 이 세션에서 이어서 하면 된다.

## 1. 결정

**vibearchive 커뮤니티(UGC 보드)는 켜지도 끄지도 않는다.** 되살리는 게 아니다.
도메인과 Next.js 골격만 재활용해서 **1인 기록 문서를 공개하는 경로**를 하나 붙인다.

- 판단 근거: UGC 보드는 cold start가 전부인데 사용자 모으기가 이 포트폴리오의 병목이고,
  국내엔 디스콰이엇 같은 메이커 커뮤니티가 이미 있다. 커뮤니티로는 승산이 낮다는 판단은 유지한다.
- 그래서 **"vibearchive를 할 것인가"를 지금 정하지 않는다.** 되돌릴 수 있는 형태로만 얹는다.
- 나중에 별도 도메인을 원하면 nginx 301로 통째로 옮긴다. 그게 탈출구다.

## 2. 왜 여기인가

| 후보 | 판정 |
|---|---|
| 새 도메인 | ✗ 권위 0에서 시작. AEO 자산이 목적인데 정면 충돌. 관리 표면만 늘어남 |
| topikvocab.foldalpha.com | ✗ 한국어 학습 앱 도메인에 개발자 문서. 주제 불일치 |
| labs.foldalpha.com | △ 루트가 foldalpha.com으로 302. 주제 정체성이 없어 권위가 안 쌓임 |
| **vibe.foldalpha.com** | **○ 채택** |

vibearchive 전제가 "AI 코딩으로 만든 프로젝트를 흘려보내지 않게 모은다"이고,
올릴 문서의 서두가 "개발 자체는 AI가 대부분 해준다, 시간과 손이 가는 건 출시 관문이다"다.
**이 사이트에 프로젝트를 올린 사람이 그다음에 부딪히는 벽이 정확히 그 문서 내용이다.**

## 3. 이미 갖춰진 것 (2026-09-16 실측)

- 공개 접근: `/` → `/discover` 200. 로그인 게이트 없음
- `app/robots.ts`: 학습봇 14종 차단 / 인용봇 11종 허용 — 이미 적용됨
- **AEO 레지스트리에 이미 등록**: `~/chart-atlas/content/aeo-sites.json`의 `vibe` 항목,
  `contentPaths = ^/(?!mcp|api/)`. **새 경로가 자동으로 콘텐츠로 잡힌다. 설정 변경 불필요**
- `app/sitemap.ts`: `STATIC_LAST_MODIFIED` 상수 관리 방식. 고정 페이지 추가는 `staticRoutes`에 한 줄

## 4. 할 일

1. 원본 복사: `~/topik-vocab/design/app-launch-playbook.md` (227줄)
2. 라우트 추가: `/guide/app-launch`
3. `app/sitemap.ts`의 `staticRoutes`에 항목 추가 + `STATIC_LAST_MODIFIED` 갱신
   (요청 시각 `new Date()` 쓰지 말 것 — 파일 주석에 이유가 적혀 있다)
4. 공개용으로 다듬기: 내부 표현("우리는") 정리, 사실은 그대로 둔다

## 5. 성격 규정 — 중요

**"개발 일기"가 아니라 "기록/레퍼런스"다.**

- 일기는 주기를 약속한다. 안 쓰면 죽은 블로그가 되고, 소회가 들어가는데 소회는 검색도 인용도 안 된다.
- 기록은 주기가 없다. 쓸 게 생겼을 때만 올린다. 이미 쓴 문서를 거르는 일이지 새로 쓰는 일이 아니다.
- 기존 SNS 톤 원칙(팩트만, 단정·소회·타인 평가 금지)을 그대로 적용한다.

후속 후보는 `~/topik-vocab/design/` 에 이미 있다 (release-procedure, aso-keyword-research,
store-submission, web-log-attribution 등). 한 편으로 끝날 주제가 아니라서 축적되는 쪽을 골랐다.

## 6. 기대치

이건 **해야 하는 일이 아니라 싸게 할 수 있는 일**이다. 반나절짜리고, 안 해도 아무것도 안 무너진다.
측정은 AEO 주간 집계에 자동으로 딸려 들어가므로 따로 볼 것은 없다.
